# model/twotower/

The two-tower architecture: a retriever and a ranker, trained separately, plus the serving core that chains them. The two training stages never talk to each other in code — only through files in `export/twotower/`.

| Stage | What it does |
|---|---|
| [`retriever/`](retriever/) | Two-tower (PyTorch). Embeds users + all ~22.8k anime into one 128-d cosine space → top-K candidates. |
| [`ranker/`](ranker/) | LightGBM lambdarank. Reranks the retriever's top 200 on 29 features. |

Both stages share one layout: `config.py`, `core/` (import-only library), one folder of runnable scripts per stage (`data_prep/`, `training/`, `export/`) and `tests/`.

Next to them: `paths.py` (this architecture's folders, `train/twotower/` and `export/twotower/`) and `serve.py` (`TwoTower`, the serving core: retrieve, rerank, cold section). `serve.py` implements the [`Recommender` contract](../README.md), which is all `service/` knows about it.

## The export bundle

`export/twotower/` (repo root) is the firewall: **retriever writes, ranker + service read.** The ranker and service import exactly one module from the retriever, [`retriever/inference.py`](retriever/inference.py) (the encoder as loaded from the bundle), never training code, and only the ranker's own two files (`ranker.txt`, `ranker_meta.json`) are written by anything other than the retriever. Full schema — shapes, dtypes, provenance — lives in `export/twotower/CONTRACT.md`, generated by `retriever/export/export.py`.

This is what lets the service stay untouched across retrains: new model, same file names, same shapes.

## Retrain loop

Run in order; each step's output feeds the next.

```bash
# 1. retriever: data/clean → train/twotower/retriever/data → best.pt → export/twotower/
for s in model/twotower/retriever/data_prep/0[1-6]_*.py; do venv/bin/python "$s"; done
venv/bin/python model/twotower/retriever/data_prep/99_verify.py
#    train on a Colab GPU: python -m model.twotower.retriever.training.runs train final --preset final,
#    then download its best.pt into train/twotower/retriever/runs/
venv/bin/python -m model.twotower.retriever.export.export && venv/bin/python -m model.twotower.retriever.export.check_export

# 2. ranker: export → pools → model → export/twotower/
venv/bin/python -m model.twotower.ranker.data_prep.build_eval
venv/bin/python -m model.twotower.ranker.training.eval --baseline-only     # sanity gate — must pass before training
venv/bin/python -m model.twotower.ranker.data_prep.build_train
venv/bin/python -m model.twotower.ranker.training.train_lgbm
venv/bin/python -m model.twotower.ranker.training.eval                     # select winner
venv/bin/python -m model.twotower.ranker.export.export
```

Training location: retriever needs a GPU (Colab); the ranker trains locally on CPU (~40 min).
